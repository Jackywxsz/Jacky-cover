# Jacky Cover

唯一默认流程：**固定纸蓝底图 → 透明互动前景 → 真实黑色渐变蒙版 → 本地文字**。背景与文字变化不再触发整张封面重绘。旧版是备份，不是第二套运行模式；用户未明确要求恢复旧版时，不读旧规则、不调用旧脚本，不以失败为理由回退。

## 先读与职责边界

1. 读取本 Skill 的 [视觉与验收规范](references/visual-system.md)；数值唯一来源是 [模板配置](references/interaction-profile.json)。不从历史prompt抄回颜色、坐标或字体。
2. 内容设计借用相邻 `../jacky-illustration/SKILL.md` 的“先理解文字，再设计画面”，以及其 `references/scene-metaphor.md`、`references/yazai-ip.md`。只继承内容理解、语义动作、芽仔身份和纸片材质；不继承其圆窗、白色窗口、上置标题、字号或尺寸规则。不要把两套完整封面规范同时送入模型。
3. 生图遵循宿主 imagegen 工具说明。只生成真正透明的互动前景，不生成固定背景、黑渐变或主标题；不要用白底/棋盘格/全图去白冒充透明。
4. 不再继承 Oil Cover 的整图生图、无人物、截图容器等运行默认。若输入真实界面，保留证据与归因，不伪造UI；本模板无法容纳完整证据时说明具体冲突，不偷偷换回旧布局。
5. 默认3:4。其他画幅需要独立版本化模板，不拉伸、裁切当前母版冒充横版。仅做本次用户需要的画幅。

## 内容任务：生成前明确语义

在项目 `analysis.md` 写清：素材来源；核心判断；主要关系；芽仔对什么做什么、产生什么结果；真人如何自然参与；遮字后能看懂什么；可删除的装饰。用户指定文案逐字保留，不能从关键词编造观点、功能、事实或结果。

芽仔是串联意义的行动者，不是角落吉祥物。一个主关系、一个紧凑场景、至多三个辅助物件。按钮、传送带、三张卡、连接线都不是固定套件。按内容选择拉、连接、筛选、阻挡、接住、搭建等动作，让动作本身传达判断。

`cover_plan.md` 记录本轮要改、已确认保留项、标题断行/强调词、小字位置、人物两臂的走向、遮挡关系、芽仔动作/材质、参考角色、待验收项。已确认方向只覆盖相应部分，不代表全图通过。

## 人物、芽仔与参考

- 真人身份只来自 `assets/jacky-reference-front.jpg` 和 `assets/jacky-reference-side.jpg` 原照片；检查原文件后实际上传。黑色圆领短袖、自然肤色、原有年龄感与头颈肩比例，无白/黄描边。不沿用失真生成脸，不拼接脸与生成身体冒充保真。
- 身份固定，动作可随内容变化；不能保证生成的新动作像素级保真。对原照检查脸型、五官、肤色，每次独立验收。
- **逐一追踪两条手臂**：肩→上臂→肘→前臂→手。允许自然遮挡但需清楚的前后关系；闲置手臂必须有合理可见去向，不能从袖口或胸口凭空结束。蒙版前后都检查，不能靠压黑掩盖缺臂。
- 肩膀、袖口及外臂留在画面内。排版只等比缩放整个前景，不压脸、缩颈、压肩、裁掉手脚来塞布局。半身/大腿构图的下缘必须进入标题后方暗部并柔和收口，不能在标题上方露出一条截腿横线；优先在生成前预留延伸，已有合格前景可使用底部alpha渐隐，不重画脸。双臂结构先在无蒙版图验收，渐隐不是修复缺臂的方法。
- 芽仔参考为相邻 `../jacky-illustration/assets/ip/yazai-paper-blue-anchor-v1.png`。大头短身、双叶绿芽、黑色无五官面罩及单侧连续反光、灰耳罩、红臂带、灰腿带、白/蓝/红胸钮和圆手脚。身份检查与材质检查独立：**薄纸片/贴纸、手绘墨线、局部纸层和浅接触阴影**；白色玩具/家电商品渲染即使身份颜色对也不通过。
- 风格参考可以约束媒介和背景，不得代替身份照片。旧封面只用于人工理解已确认布局，不作为失真人像的递归生成源。

## 制作与可重复合成

1. 检查并复用 `assets/covers/` 中的v3参考图固定母版和独立黑蒙版，不能让生成模型重画或把黑渐变预烘焙进前景。参数与文件hash由合成工具检查。底图以用户指定参考图还原后的固定PNG为准；右上方是较宽的柔蓝过渡，左侧中下部也有蓝晕，不能擅自缩成极小角落点缀或改成左右对称蓝边。人物上部保持清晰，深黑集中到标题附近。
2. 生成一张**不含背景、文字、黑遮罩**的透明前景，只含真人、芽仔和必要物件。保持所有关键肢体完整，构图留出手写补充区。工具输出alpha不合格就修前景，不能改回整图生成。
3. 打开透明前景，检查原照身份、两臂、芽仔纸片风和语义动作。合成器把可见alpha边界整体等比装入固定前景安全区，不裁切；下缘允许位于主标题后方，以底部88px的平滑alpha渐隐收口；源画布比例不限，输出严格使用模板比例。先看构图是否合理，再排字。
4. 写项目 `text.json`：`lines` 为两行数组，每行包含 `text` 和可选的逐字 `emphasis`（该行最多出现一次，橙色）。可选 `note` 包含 `text`、归一化 `xy` 和 `size`；小字随实际留白定位，必须与前景、主标不碰撞。不要机械居中或强制固定在芽仔下面。
5. 运行唯一合成入口；字体候选只用于定位真实同名文件，内部family/style必须匹配，缺失即停止。可显式用 `--font` / `--note-font` 指定已存在同家族字体，不安装、不静默替换。

```sh
python3 scripts/compose_interaction_cover.py --scene /absolute/scene.png --text /absolute/text.json --output /absolute/cover.png --report /absolute/report.json --layers-dir /absolute/new-layers
```

项目路径由任务目录决定，不把用户的个人路径写进共享配置。主标题、小字和蒙版都由本地真实图层生成；标题字号/颜色变更只重新合成，前景源文件保持不变。保留背景、场景、蒙版和文字层，报告包含实际字体、hash、alpha锚点、尺寸和缩放。

6. 看成图、270×360缩略图及人物/芽仔局部，记录人工验收。脚本通过只证明数值/文件/边界成立，不能证明“像本人”“双臂自然”或“隐喻准确”。

## 失败与交付

每轮前景最多一次针对性生成式修订；失败版不晋升为身份或材质锚点。背景/文字/蒙版问题只修对应源层。连续身份漂移时回原照，不能对生成脸继续叠改。用户接受的原照抠像可作为另一种前景来源，但只能用其真实姿态，不制造不存在的肢体。

交付项目自己的输出版本，附当前合成配置、字体/图层报告和视觉检查。`user_acceptance` 与 `self_check` 分开。模板技术检查通过与多次内容任务稳定通过是两回事；一次演示不能宣称长期稳定。

维护命令：`python3 scripts/compose_interaction_cover.py --build-template` 核验固定参考底图并从唯一配置生成黑蒙版；固定底图不可由参数重新猜测生成；已有资产不一致时拒绝覆盖。配置升级须新模板版本和新资产，不直接改旧PNG。回归：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`。
